# Antigravity Spec: Waitlist Backend API (Vercel Serverless)

## 1. Objective
Implement a Vercel Serverless Function to handle waitlist signups from the `ple.simway.io` landing page. The function must accept an email address and fan it out to three destinations: Resend (for marketing), Vercel KV (for backup storage), and Discord Webhook (for team notifications).

## 2. Architecture & Trigger
- **Endpoint:** `/api/waitlist` (HTTP POST)
- **Environment:** Vercel Serverless Functions (Node.js)
- **Input Payload:** `{"email": "user@example.com"}`

## 3. The Triad Fan-Out (Parallel Execution)
The function should validate the email and then concurrently push to:

1.  **Vercel KV (The Vault):**
    - Store the email as a key, or append to a set of waitlist emails.
    - Captures timestamp.
2.  **Resend API (The Engine):**
    - Add the email to the predefined Resend Audience/Contact List.
3.  **Discord Webhook (The Pulse):**
    - Send a formatted message to the `simway-channel` webhook.
    - Format: "🦞 **New Waitlist Lead:** `[email]` has joined the queue!"

## 4. Environment Variables Required
The following must be added to the Vercel Project Settings by Sim:
- `KV_REST_API_URL` & `KV_REST_API_TOKEN` (Auto-generated by Vercel KV)
- `RESEND_API_KEY`
- `RESEND_AUDIENCE_ID`
- `DISCORD_WEBHOOK_URL`

## 5. Execution Mandate for Gaudí
- Do not modify `index.html` UI beyond pointing the form to `/api/waitlist`.
- Use `fetch` for Resend and Discord to avoid heavy SDK dependencies if possible, or use minimal SDKs.
- Graceful failure: If Discord fails, do not fail the whole request. If KV or Resend fails, log error but try to succeed on the others. Return a 200 OK to the frontend as long as the email was captured *somewhere*.
## 6. SECURITY MANDATE (CRITICAL)
- **PUBLIC REPOSITORY:** `ple.simway.io` is a PUBLIC repository.
- **ZERO HARDCODED SECRETS:** You MUST NOT hardcode any API keys, webhook URLs, or tokens in the code. All credentials must be accessed strictly via `process.env`.
- **CORS:** Ensure the API endpoint only accepts requests from our own domain (or allow all for now, but ensure no sensitive data is leaked).
